# Forbidden brand tokens for scripts/branding-audit.sh. One POSIX extended
# regular expression per line, matched case-insensitively at word boundaries
# (grep -wiE). '#' starts a comment line; blank lines are ignored. This file is
# excluded from the scan so the tokens can be written here in plain text.
# "808" / "909" on their own and "mw909" are allowed and must not be matched.

# The audit also matches every line normalised: typographic dashes become
# '-', camelCase humps are split (see scripts/branding-audit.sh), so the
# patterns here only need ASCII separators. "TR[-./]" covers TR-909, TR.909,
# TR/909 and, after normalisation, TR–909 / TR‑909 / TR—909.

# A line starting with "text:" applies to the text scan only. Short codes that
# occur by chance in the random byte runs of a binary are text-only; their
# hyphenated spellings are checked everywhere.

# --- the original manufacturer and its product marks ---------------------------
Roland
TR[-./][0-9]{1,3}[A-Z]?
text:TR[0-9]{1,3}[A-Z]?
CR[-./][0-9]{2,4}
text:CR[0-9]{2,4}
Rhythm[[:space:]_-]*Composer
text:ACB

# --- 909-specific marks, clones and sample/emulation vendors ----------------------
# TR-909, TR-09, TR-8, TR-8S, RD-9 and the "TR909" spelling are already caught
# by the TR-/RD- patterns above; this adds the space-separated spelling.
text:TR[[:space:]]+[0-9]{1,3}[A-Z]?
# The model numbers run into an identifier or test name (tr909_shuffle,
# TR_808): three digits, so it stays safe in binaries too.
TR_?[0-9]{3}[A-Z]?
# D16 Group (Drumazon, Nepheton, Phoscyon). A bare "D16" is not listed: it is
# also a schematic component reference (diode D16), which research-derived
# comments use.
D16[[:space:]_-]*(Group|Audio)
Phoscyon
# AudioRealism's drum machines (the company is caught above).
ReDominator
Wave[[:space:]_-]*Alchemy
# Softube, and its 909-style instrument. A bare "Heartbeat" is not listed: it

# spellings are forbidden.
Softube
